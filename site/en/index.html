HTTP2Shell: critical bug in Brotli

A critical bug in Brotli, Google’s compression: HTTP2Shell. Brotli is in Node.js, in Python, in Bun, Envoy and Istio, and probably in something of yours. The patch is out: Brotli 1.2.1, Node.js 26.12.1, 24.22.1 and 22.23.4. Don’t panic. Do update.

21:27Brotli’s own fix has been out since 21 October, 19:27 UTC. Node.js had it the same day. Every minute on this clock is a minute without an update. Is the patch there for me?

What is going on?

What is Brotli?
A way to make data smaller, like zip and gzip. Jyrki Alakuijala and Zoltán Szabadka of Google designed it in 2013, at first for web fonts. It is named after a Swiss bread roll, the Brötli. Since 2016 it is an internet standard: RFC 7932. Every major browser speaks it, CDNs send it, and a WOFF2 web font is always Brotli. So whatever fetches something from the internet often gets Brotli back and has to unpack it.
The bug
An out-of-bounds write in Google’s Brotli decoder: CVE-2026-111497, also called HTTP2Shell, first Node2Shell. The decoder cannot tell broken input from input that is not complete yet, goes on in an invalid state and writes outside its own memory. The fix gives broken input its own error code: -17.
Which way?
Both. A server that unpacks Brotli is open to a malicious client. A client that unpacks Brotli is open to a malicious server. That is almost every HTTP client: it asks for Brotli itself, with Accept-Encoding: br.
How bad?
CVSS v4.0 9.2, from Google in the CVE record. Node.js calls it high. Ubuntu says medium. The Dutch NCSC: likelihood medium, impact high. Four parties, four opinions. All four answer: patch. An attacker can corrupt memory with one compressed message, leak data, crash the program and possibly run their own code.
Which versions?
Brotli 1.0.3 up to and including 1.2.0. Every program with its own copy of Brotli has to update by itself.
Who has it?
Node.js, with its own copy. The Python packages brotli and brotlicffi, and through them requests, urllib3, httpx, aiohttp and Scrapy, even if your code never says import brotli. According to Aikido also Bun, Envoy and Istio. Not affected: Apache with mod_brotli and nginx, because by default they only compress.
Who found it?
OpenAI’s Codex Security, says the Node.js advisory, back in February. Brotli fixed the code then, but did not see it as a security bug. So there was no release then. There is now.
Exploited?
Yes. On 27 October the US CISA added the bug to its KEV catalog, the list of vulnerabilities known to be exploited (alert). Italy’s CSIRT reports exploitation too, writes Security.NL. CISA does not say how or against whom. Before that it was “not seen yet” (The Hacker News, 22 October; the Dutch NCSC on 23 October).
Does my scanner see it?
Since recently. Since 23 October, 21:08 CEST, GHSA-9v8h-qqgm-4m35 on GitHub names the Python packages, so Dependabot should see them now. Using pip-audit or Safety? Check by hand.

What should you do?

Stay indoors. Do not unpack anything.

  1. Find out where you have Brotli. Also where you do not expect it. Check every virtualenv and every container image on its own. 
    node -v
pip list 2>/dev/null | grep -iE '^brotli'
dpkg -l | grep -i brotli        # Debian, Ubuntu
rpm -qa | grep -i brotli        # Fedora, RHEL, openSUSE
  2. Node.js: update to 26.12.1, 24.22.1 or 22.23.4. The official Docker images node:24.22.1 and up have been there since 22 October. Recreate your containers, a restart is not enough. Still on Node.js 20? Then this is a good moment.
  3. Python: is brotli or brotlicffi in the list? Upgrade it, and put the new version in your lockfile too. 
    pip install --upgrade 'brotli>=1.2.1'           # if you have brotli
pip install --upgrade 'brotlicffi>=1.2.1.0'     # if you have brotlicffi
  4. The system package: Debian 13 has 1.1.0-2+deb13u1, Debian 12 has 1.0.9-2+deb12u1. Debian’s Node.js uses that system library. Update, then restart: 
    sudo apt update
sudo apt install --only-upgrade libbrotli1
sudo needrestart -r l          # what still runs old code?
  5. Cannot update yet? Then Aikido lists three stopgaps. One: remove brotli and brotlicffi; HTTP clients fall back to gzip. Two: refuse requests with Content-Encoding: br at the proxy. Three: take br out of Accept-Encoding and refuse Brotli responses before unpacking. Changing the header alone is not enough: a malicious server sends Brotli anyway.
  6. Do not click links in emails about this bug. We never email. And if we did, it would be gzipped.
