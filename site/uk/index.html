TCP2Shell: вразливість у TCP-коді Linux

Вразливість у тому, як ядро Linux встановлює TCP-зʼєднання: TCP2Shell. За даними Anthropic, зловмисник може з її допомогою віддалено отримати root, без входу в систему, на сервері з MPTCP. Debian, SUSE і Oracle вже мають виправлення, Ubuntu і Red Hat ще ні. Без паніки. Але додайте правило до брандмауера.

15.10.2026З 15 жовтня виправлення є в ядрі. Ubuntu і Red Hat його ще не постачають. Кожна хвилина на цьому годиннику є хвилиною з правилом у брандмауері. Чи є виправлення для мене?

Що відбувається?

Вразливість
CVE-2026-98432: use-after-free у коді ядра для IPv4 TCP. Під час встановлення зʼєднання з IP-опціями (Record Route або Timestamp) ядро може прочитати памʼять, яку щойно звільнено, якщо повторно надісланий SYN одночасно обробляється на іншому процесорі. Вона існує з ядра 4.4, тобто з 2016 року. IPv6 не вражено.
Що таке MPTCP?
Multipath TCP: одне зʼєднання одразу через кілька мережевих шляхів, наприклад wifi і 4G на телефоні. Якщо один шлях зникає, зʼєднання продовжується через інший. Це розширення TCP (RFC 8684). Apple використовує його на iPhone з 2013 року, зокрема для Siri, а Linux підтримує його з ядра 5.6 (mptcp.dev, Wikipedia). Для решти інтернету це виглядає як звичайний TCP. Дві дороги до Рима. І для зловмисника теж.
Чому воно увімкнене?
MPTCP є в ядрі, але програма має сама його попросити. Майже жодна програма цього не робить. Окрім усього, що написано на Go: починаючи з Go 1.24, що вийшов у лютому 2025 року, сервер на Go за замовчуванням просить у ядра MPTCP, як зазначено в примітках до випуску. Програмісту нічого не треба робити, і зазвичай він про це навіть не знає. Сам Go не вразливий. Він лише відчиняє двері до тієї частини ядра, яка вразлива.
Що може зловмисник?
Frontier Red Team компанії Anthropic 27 жовтня написала, що ще не випущена модель Claude створила з її допомогою робочий експлойт: віддалено, без входу в систему, root на сервері з MPTCP-слухачем (Anthropic). Витік вказівника ядра зайняв 48 хвилин, оболонка ще пʼять. Експлойт не опубліковано. Чи працює це без MPTCP, невідомо. Так, Claude є родичем автора цієї сторінки. Вдома ми про це ще не говорили.
Серйозність
CVSS 9,8 від команди CVE ядра. Red Hat каже 8,1, «Important»: гонку важко виграти. Feedly каже 5,9. Три сторони, три числа. Усі три: оновлюйте.
Які версії?
Усе, починаючи з 4.4. Виправлення є у 5.10.272, 5.15.223, 6.1.190, 6.6.159, 6.12.113, 6.18.56, 7.2.10 і 7.3.
Чи є атаки?
Поки не помічено. Вразливості немає в каталозі KEV агентства CISA, а експлойт Anthropic не оприлюднено.
Чому TCP2Shell?
Власної назви вразливість не має. Після PHP2Shell і HTTP2Shell команда кризи вже не могла зупинитися.

Що вам робити?

Залишайтеся вдома. Тримайте двері зачиненими.

  1. Перевірте, чи має ваше ядро виправлення. Debian 13 має 6.12.113-1, Debian 12 має 6.1.190-1. Оновіть і перезавантажте, інакше працюватиме старе ядро: 
    uname -r
sudo apt update && sudo apt full-upgrade
sudo reboot
  2. Виправлення ще немає? (Ubuntu, Red Hat, стандартне ядро Amazon Linux 2023.) Тоді не пропускайте TCP-пакети з опціями IPv4. Звичайний трафік їх не використовує; RFC 7126 уже радить їх відфільтровувати. Це правило від RFF: 
    sudo nft add table ip cve_2026_98432
sudo nft add chain ip cve_2026_98432 pre '{ type filter hook prerouting priority -300; }'
sudo nft add rule ip cve_2026_98432 pre meta l4proto tcp ip hdrlength gt 5 counter drop
    Після перезавантаження воно зникне, якщо його не зберегти. Ваша мережа використовує мітки CIPSO (SELinux або Smack із NetLabel)? Тоді не застосовуйте його, їм ці опції потрібні.
  3. Маєте сервіси на Go? Вимкніть MPTCP, доки ядро не буде оновлено, і перезапустіть сервіс: 
    GODEBUG=multipathtcp=0          # Go 1.24 і новіші
sudo ss -lnMp                   # які процеси слухають із MPTCP?
  4. Не натискайте на посилання в листах про цю вразливість. Ми ніколи не надсилаємо листів. А якби надсилали, то лише одним шляхом.
